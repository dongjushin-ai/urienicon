# 0001. 리소 변환은 CPU 경로를 먼저 쓰고, GPU 셰이더는 측정 결과로 결정

- 날짜: 2026-11-02
- 상태: 채택 (실기기 측정 후 재검토)
- 관련: 이슈 #4, docs/design.md 10장

## 배경
설계서는 리소 변환을 GPU 셰이더(≤150ms)로 하고 CPU(`image`/Isolate, ≤1초)를 대체 경로로 두었다.
S1에서 CPU 기준 구현(`lib/riso/riso.dart`)을 먼저 만들고 속도를 쟀다.

## 측정
| 환경 | 입력 | 결과 |
|---|---|---|
| Linux x86 서버, AOT(`dart compile exe`) | 1024×681 누끼 | 중앙값 89ms |
| 중급 Android(예상, 단일 코어 3~5배 느림) | 같은 입력 | 약 300~450ms |

재현: `dart compile exe tool/riso_bench.dart -o riso_bench && ./riso_bench <누끼 PNG>`

## 결정
- S1~S2는 CPU 경로(`compute`로 UI 스레드 밖)만 쓴다. CPU 목표 ≤1초 안에 들어오고, 변환은 사진당 1번(12컷은 결과를 회전·반전·배치)이라 체감 지연이 작다.
- GPU 셰이더는 **실기기 중급기 측정 중앙값이 400ms를 넘을 때만** 만든다. 만들면 CPU 결과를 정답(골든)으로 두고 비교한다.

## 이유
- 셰이더는 기기·드라이버마다 결과가 미세하게 달라 "같은 사진은 같은 결과"를 깨기 쉽고, 테스트하기 어렵다.
- 거리 변환·연결 덩어리 제거는 셰이더로 옮기기 어려워 어차피 CPU에 남는다.
- 필요 없는 경로를 유지하는 비용 > 아낄 수 있는 0.2~0.3초.

## 재검토 조건
- H0 측정 때 스파이크 화면의 "리소 변환 (CPU)" 시간이 중급기 중앙값 400ms 초과
- S2에서 컷마다 변환이 필요해지는 설계 변경
